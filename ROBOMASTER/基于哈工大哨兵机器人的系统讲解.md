# 基于哈工大哨兵机器人的系统讲解

> 本文为技术分享的听讲记录，与2026-09-13 使用AI重新排版。内容按原记录保留，只做分层与断句。

## 体系化认识

- 完全要求全自动，事实上最好所有兵种都全自动
- 步兵 / 英雄：要考虑操作手怎么开才习惯，主导方是机械，由机械定样板
- 哨兵强行关联算法与电控，所以机器人在一开始做设计时，就要考虑算法的可实现性
- 核心目的：跑自动 / 自动化

## 一、机械

### 雷达

- 用起来需要沟通：算法要提需求给机械的人（扫描范围、工业相机等）
- 态势感知能力要求高于其他兵种，因此使用双雷达；雷达应当放在空旷处
- 定位是否使用对天定位？
- 建图：做适应性建图，原点使用天上的某些特征做匹配，把天花板的特征当作地图（天花板结构太单一就不要用这种方案）；边建图边导航，还有搜索方案，以及里程计
- 辅助建图后面使用

### 相机与云台

- 云台整体设计：设计俯仰角和空间关系时，要想清楚战术定位上要能打多远的敌人。打近处则云台前置；放得高才打得到远处。没考虑到攻击范围，范围就会很小
- 镜头焦距：8mm / 12mm 焦距太近，无法打到远处的敌人（无法识别特征）
- 各兵种都会配工业相机，小摄像头用于拓展视野、做全向感知，更好地判别周围敌人、攻击高价值目标
- 扫描时 pitch 和 yaw 轴会一直转，类似点头的状态；有操作手的人会躲避索敌范围

### 算力与方案

- 方案 B：哨兵和雷达站联动（7V7）
- miniPC 用 i7，或双 PC（以防资源不够用）
- 实际上还好，主要吃内存，要用大一点的卡
- 哨兵应当明确自己要装什么（东西很多），需要有接线图，最开始做设计的人一定要先定好
- 硬件找软件画接线图，需要开会讨论？

### 接线与供电

- CAN 线会有负载：总线上的消息过多会出现堵塞，进而电机无法收发、开始抽风
- 频率拉高会导致链路上出现阻塞
- 遥控器有规定型号（不推荐），使用图传链路，保底方案用遥控器，有官方例程
- 裁判系统 - 图传模块：操作指令利用链路传给机器人
- DT7 不好买；天地飞（只能买黑色）
- 电滑环：机械要求；是否过弹丸；下供弹要求下链路引出来，需要中心滑环
- 裁判系统至少留四根线：信号 CAN 需要 1-2 条，一条 CAN 两根，两条 CAN 要四根；正负极电流要留回来；需要电机；裁判系统需要三路供电、电源管理模块
- 滑环供电需要四条
- 供电对象：上云台、miniPC、发射机构
- 主控板和小电脑放在 miniPC 上，因为这里的电路可以稳定供电
- 不一定支持热插拔：i7 不要热插拔，哨兵直接下电会烧
- 高频信号不推荐过滑环，会影响通信质量、会丢包

### 供弹

- 供弹方式分上供弹、半下供弹、全下供弹，取决于放在哪个运动系：yaw 与 pitch 之间为半下，pitch 以上为全上供弹，底盘为全下供弹
- 单纯使用 PID 时，满弹和空弹的模型不一致；上供弹给 pitch 轴的负担过大
- 弹舱顶端做得过大，会牵连下面全部加大
- 惯量尽量往下放；下供弹不需要留一个大脑袋 / 大肚子，这样惯量可以很小
- 拨盘给弹丸一个初始运动速度，让它从弹舱运动到整个弹链，经过很长的管道，一个接一个推上去
- 整个供弹需要一体化的设计思路；下供弹的直角弯要设计好，否则会卡住
- 鹅颈设计很复杂，去学的话会有领悟
- 侧供弹拐来拐去很抽象，会经过多个直角弯，鹅颈可能至少有三个弯，但凡有一个出问题都会寄
- 问题在于：结构坑点太多，调试时间又不够，所以要一版一版迭代，不要怕试错
- 操作手造完之后直接开始打，要多调；轴承要定期换（会生锈），需要重新更新一遍；易损件、轴承、螺丝要全部换一批。但车设计得不好，会修坏

## 二、模块化设计

- 若哨兵和步兵都用鹅颈，可以给同一个人做，节省人力资源
- 轮组要做快拆：RM 场上工作强度很高，不可避免要更换、维修，设计之初就要考虑快拆（如换云台、轮组等）
- 上供弹的好处：几乎可以忽略重力补偿
- 鹅颈的重力会积累在前端，需要电机补偿产生静力矩，会产生积热
- 广东工业大学的机械结构值得看
- 拉一根弹簧（用处没听清楚），电控的运动模型会更加痛苦
- 我们的车辆底盘是井字形构架，留给硬件的就周边四块
- 电池要跟着电管放，接线要自己研究；需要考虑电管给云台走线，从滑环走过去
- RFID 场地交互模块：增益点、回血，停在位置上 RFID 就能识别到场地卡。由于附近大电流模块很多、干扰严重，CAN 线要买屏蔽线（有点粗）。到场地后要测试 RFID，因为可能漏磁，会出现识别不到的情况
- 主动屏蔽手段：买带胶的铝箔纸，不要直接贴在 RFID 上，机械应当画一个板子贴在上面；CAN 线一定要注意
- 硬件要做好插接头并做到 PCB 上：但凡多一个接头，车上就多一个不稳定点；可以直接上热熔胶 / 红胶
- 不要出现杜邦线，多用接头
- 如果某个地方很容易松，可以上红胶把螺帽胶死

## 三、电控

- 硬件平台：STM32F4 / H7
- 工具链：OZONE、VS Code、Keil MDK5
- 控制算法能简单就简单、能稳定就稳定，有多线程调度层
- 双 yaw 流动可能出现严重的相互干扰，可以使用 LQR 或较简单的 PID
- 机器人动力学、控制算法（经典 / 现代）
- 力控底盘：主要可用中科大的力控底盘
- 速度控制底盘：使用速度闭环
- 参考书：东北大学机器人开源的书《》（书名未记全），以及另一本控制算法经典书籍（没听清）
- 功率控制是一个很重要的内容
- 直接建模辨识参数（）
- 先看赛规：如果车开太快、电管真的过了 300W，会直接扣血
- RLS 递推推导
- 直接看越鹿框架
- 裁判系统要双向通信：枪口热量、机器人血量
- 第二个裁判系统是有 UI 的
- 材料力学、理论力学是机械基础的书

## 四、算法

- 算法自己看导航开源：看它是怎么跑的、基于哪篇论文、依据是什么，才能知道它的局限性在哪
- navigation2 是比较重要的开发器，多看；生态好、用的队伍多（哈工大的很复杂）
- 对程序要有模块化思维：分为几个模块、是怎么跑起来的，需要有系统思维

### 自瞄

- 自瞄学好之后直接接触同济大学 SuperPower 的框架，看框架和论文、看数据流图、看各个线程是怎么跑的、怎么用的，对抽象认识很有用
- 轨迹优化的理论使用的是 MPC，非线性控制系统的优化（相对高阶）
- 分层结构：
  1. **感知层** —— 接收相机摄取的画面
  2. **特征处理层** —— ① 基于 OpenCV 的传统视觉：计算快、准确率高；② 基于神经网络（YOLO）：环境适应能力强、精度稍低。这会影响场上调试，对哨兵和自瞄步兵影响大
  3. **坐标计算层** —— 装甲板图案有四个角点，两个灯条的四个角点是物理基础；识别到四个角点后，先读出相隔多少个像素，通过长宽对比可以计算大致距离
  4. **位姿计算层** —— 判断在什么位置、什么姿态，根据敌人坐标计算出仰角
  5. **运动解算层** —— 云台究竟要算到 yaw 轴和 pitch 轴什么角度，还有弹道解算
  6. **运动预测层** —— 由位姿计算层引出，根据装甲板实际移动过了多少毫秒来预测，这些要考虑卡尔曼滤波
  7. **通信层** —— 与电控通信，把云台角度 yaw、pitch 轴发送到通信层

### 导航

- 导航看 24 年 / 25 年北理莫斯科大学北极熊战队的开源
- 导航的算法复杂度比自瞄高
- 感知层：雷达发激光，计算回波距离，可知距离障碍物有多远；以比较高的频率扫描，可以在一个视野范围内感知出三维图，进入导航处理，先建出一张图（原记录未记下名称），较为复杂
- 导航算法比自瞄多很多，但调试参数没有自瞄多，调试时间比自瞄更少
- 尽快学好基础，之前就分好工
- 学习框架：直接在脑子里画出模块，做出框架图
