# 算法组入门（要求 + 学习路径）

> 本文合并《[[25算法组学习要求]]》与《[[算法组开源代码学习路径]]》两篇并去掉重复内容，作为算法组新人的单一入口。原两篇保持原样，未做改动。

## 一、算法组成员要求

### 1.1 本组必备技能

**环境** —— 分清 Linux 与 Windows 的区别，熟练使用命令行和终端；会装虚拟机、WSL、双系统；在 Linux 里装好 ROS 2；会用 VS Code。

**算法** —— 了解 cv2 与 YOLO；掌握完整的训练链条：采数据 → 标注 → 训练 → 导出 ONNX → 转 OpenVINO IR → 部署验证。

**接口与硬件** —— 懂通信协议（串口 / CAN、数据格式、校验方式）；会相机内参标定与手眼标定；了解镜头选型、曝光设置、雷达的安装角度与坐标系。

**实时性** —— 自瞄和导航是实时系统，不能只看"能不能跑"，还要看帧率和延迟。参照指标：自瞄帧率约 100 FPS。

**协作** —— 会用 Git（分支、提交、PR）；会用 AI 处理技术难点和重复性工作；会用 Obsidian 维护知识库；主动把学过的东西写成文档。

**开源代码** —— 读懂同济 SuperPower（自瞄）和北极熊（导航）的代码，理解模块划分，能按战队需求修改结构和参数。

> 优先级：环境 → 自瞄主流程 → 导航主流程 → 训练链 → 接口与硬件 → 协作工具。25 级以速成为主，时间不够时按这个顺序取舍。

### 1.2 算法组外但应当具备（面向 26 级）

本条主要面向 26 级。25 级以 1.1 为第一要务，以速成为主。

作为 RM 成员还应会：使用 AI（配置 API、掌握 harness 技巧）、焊接电路板与导线、使用单片机、C/C++/Python 基础（至少到函数）、拓竹 3D 打印与 Bambu Studio（上料 / 退料 / 检修）、基础 SolidWorks、翻墙（可选）。

## 二、学习路径

25 级面临的问题很直接：算法底层原理复杂，C++ 至少要学到面向对象，而 25 电气系的 C 语言课连指针和函数都没认真教。必须承认 25 级在代码层面约等于零基础，因此要在速成与打牢基础之间取平衡，且偏向速成。

起点是本部教材：上海大学【27SRM培训】算法组 1-5 讲。它默认你已学完 C++ 语言类内容，看不懂很正常，先整体概览一遍。

### 2.1 自瞄：从能跑到看懂

**阅读顺序**

1. 读 [`readme.md`](https://github.com/TongjiSuperPower/sp_vision_25)，重点第 3.4 节（软件架构）和第 4 章（轨迹视角下的自瞄理论）
2. `src/standard.cpp`，只有 83 行，是整个项目最短最完整的主流程
3. `tests/auto_aim_test.cpp`，最有用的入口：不用相机、不用机器人，直接读 `assets/demo/demo.avi` 和配套的四元数文件就能跑。想改代码看效果就改它
4. 按需深入 `tasks/auto_aim/`，先看 `.hpp` 接口，再看 `.cpp` 实现

**主流程就是六句话**（`src/standard.cpp` 第 57~80 行）

```cpp
camera.read(img, t);                    // 1 取一帧图像 + 时间戳
q = cboard.imu_at(t - 1ms);             // 2 取"拍这张图时"云台姿态四元数
detector.detect(img);                   // 3 识别：图 → 装甲板列表
tracker.track(armors, t);               // 4 估计：装甲板 → 整车运动状态
aimer.aim(targets, t, bullet_speed);    // 5 决策：目标状态 → 云台角度 + 是否开火
cboard.send(command);                   // 6 指令下发
```

两个容易忽略但很关键的点：

- 第 2 步的 `t - 1ms` 是时间对齐。图像来自相机、姿态来自电控，时间戳对不上，后面算出来的位置全是错的。
- 第 3 步和第 4 步的区别：识别器只回答"这一帧看到了几块装甲板"，估计器回答"敌方整车在怎么动"——旋转中心、角速度、朝向、各装甲板半径。只有有了整车状态，才能预测 10 秒后它转到哪。

**分层与代码对照**

| 分层 | 职责 | `sp_vision_25` 中的位置 |
|---|---|---|
| 感知层 | 拿到相机图像和时间戳 | `io/camera.cpp` |
| 特征处理层 | 从图中找出装甲板 | `detector.cpp`（传统）、`yolos/yolo11.cpp`（神经网络） |
| 坐标计算层 | 四个角点像素 → 距离 | `solver.cpp` |
| 位姿计算层 | 位置 + 姿态 → 仰角 | `solver.cpp`、`armor.cpp` |
| 运动解算与预测层 | 算 yaw/pitch、弹道解算、预测目标位置 | `tracker.cpp`、`target.cpp`、`tools/trajectory.hpp`、`aimer.cpp` |
| 通信层 | 把角度指令发给电控 | `io/cboard.cpp`、`io/serial`、`io/socketcan.hpp` |

**两条识别路线的取舍**

| 路线 | 优点 | 代价 |
|---|---|---|
| OpenCV 传统视觉 | 算得快、精度高 | 依赖光照和颜色阈值，换场地容易失效 |
| YOLO 神经网络 | 环境适应能力强 | 精度略低，推理耗时影响帧率 |

这个取舍直接决定场上调试的难度，对**哨兵和自瞄步兵**影响最大——这两者面对的环境最不可控。

**轨迹优化与 MPC**

自瞄的决策器用的是轨迹优化，理论上是 MPC（模型预测控制，非线性控制系统优化），属于高阶内容。

代码入口：`tasks/auto_aim/planner/tinympc/`，使用的是 TinyMPC 库。

值得注意的设计选择：同济把 MPC 当**求解器**用（用来找一条满足约束的可行轨迹），而不是当闭环控制器。他们试过直接拿 MPC 做闭环控制，效果反而不如下位机方案。这就是"看清依据才知道局限"的实例——MPC 的前提是模型准确、算力充足，条件不满足时它并不占优。

### 2.2 导航：从能跑到看懂

导航的系统复杂度比自瞄高得多（算法数量多很多），但**调试参数反而比自瞄少，调试时间更短**。这条结论对分工有直接意义。

参考开源：[pb2025_sentry_nav](https://github.com/SMBU-PolarBear-Robotics-Team/pb2025_sentry_nav)（深圳北理莫斯科大学北极熊战队，25 赛季哨兵），已下载到 `06_开源参考/`。它基于 ROS 2 的 [Nav2](https://github.com/ros-navigation/navigation2) 框架，结构清晰，是学导航最合适的材料。

**阅读顺序**

1. 读 `README.md`，重点是数据流和坐标变换那两段。坐标系很多（`lidar_odom`、`odom`、`chassis`），看不懂这个后面全是懵的
2. 找入口：`pb2025_nav_bringup/launch/` 下的 `rm_navigation_reality_launch.py`（实车）和 `rm_navigation_simulation_launch.py`（仿真）。一个 launch 文件就是一张"谁在跑"的名单
3. 看参数：`pb2025_nav_bringup/config/reality/nav2_params.yaml`，这是理解规划与控制最快的入口，比读代码直观
4. 按包深入：每个包先读 `package.xml` 的 description 和头文件，再看 `src/`
5. 建议的深入顺序：`point_lio`（依据 LOAM 论文）→ `small_gicp_relocalization` → `terrain_analysis` → `pb_nav2_plugins` → `pb_omni_pid_pursuit_controller`。数据转换桥遇到再看：`loam_interface`、`sensor_scan_generation`、`pointcloud_to_laserscan`、`fake_vel_transform`

**分层**

1. **感知层**：激光雷达高频扫描 → 回波测距 → 视野内的三维点云
2. **里程计（LIO）**：点云 + IMU → 自己在哪里、怎么动的（`point_lio`，依据 LOAM 论文）
3. **建图 / 重定位**：先建地图，之后靠地图匹配找回自己的位置（`small_gicp_relocalization`）
4. **数据处理桥**：坐标系转换、点云转激光扫描（`loam_interface`、`sensor_scan_generation`、`pointcloud_to_laserscan`）
5. **可通行性分析**：哪些地方能走、坡度多大（`terrain_analysis`、`terrain_analysis_ext`）
6. **规划与控制**：全局路径 + 局部跟踪（Nav2 全局规划器 + `pb_omni_pid_pursuit_controller`）
7. **决策**：行为树（`behavior_trees/`）

**要掌握的 Nav2 概念**

建图（SLAM Toolbox）、定位（AMCL / 重定位）、代价地图（costmap，分全局和局部）、全局规划器、局部控制器、行为树。看代码前先把这几个概念搞清楚，否则读 launch 和 yaml 会一头雾水。

**北极熊仓库的包清单**

| 包 | 作用 |
|---|---|
| `livox_ros_driver2` | Livox mid360 雷达驱动 |
| `point_lio` | 激光惯性里程计，输出配准后的点云 |
| `loam_interface` | 把 `point_lio` 的点云从 `lidar_odom` 系转到 `odom` 系 |
| `sensor_scan_generation` | 把点云转到雷达系，并发布 `odom -> chassis` 变换 |
| `small_gicp_relocalization` | 用 small_gicp 做重定位 |
| `pointcloud_to_laserscan` | 三维点云转二维激光扫描 |
| `terrain_analysis` / `terrain_analysis_ext` | 地形分析，判断可通行性 |
| `pb_nav2_plugins` | 为 Nav2 写的自定义插件（代价地图层、行为树节点） |
| `pb_omni_pid_pursuit_controller` | 全向 PID 追踪控制器，替代 Nav2 默认控制器 |
| `fake_vel_transform` | 底盘坐标系变化时，转换 Nav2 下发的速度指令 |
| `pb_teleop_twist_joy` | 手柄遥控（底盘 + 云台） |
| `pb2025_nav_bringup` | 总启动配置：launch、config、地图、pcd、rviz、行为树 |
| `pb2025_sentry_nav` | 元包 |

### 2.3 实践与仿真

虚拟机里没有工业相机、也没有可用显卡，仿真（[pb_rm_simulation](https://github.com/LihanChen2004/pb_rm_simulation)）是唯一能动手跑起来的环境。先把仿真跑通，再谈上真车。

### 2.4 环境清单（版本是绑定的）

Ubuntu 22.04 + ROS 2 Humble + OpenVINO 2024.6 + CMake 3.22 + OpenCV 4.5.4。

两个已踩过的坑：

- **换行符**：Windows 上 `core.autocrlf=true` 会把 LF 换成 CRLF，搬到 Linux 后脚本报 `bad interpreter`。解决：`git config --global core.autocrlf input`，或用 VS Code 远程连虚拟机编辑。
- **OpenVINO ABI**：Python 版 OpenVINO 包（含清华镜像）用的是旧 C++ ABI，和系统的 OpenCV、yaml-cpp 冲突，链接时报大量 `undefined reference`。要用 Intel 官方 apt 源的 `libopenvino-*` 包。判断方法：`nm -D --defined-only libopenvino.so | c++filt | grep read_model`，出现 `std::__cxx11::` 才是新 ABI。

## 三、验收标准

- **最低**：掌握基本 C++，看得懂代码，知道 YOLO 和 cv2
- **合格**：掌握自瞄或导航的整体代码结构，会训练 YOLO，会用 cv2，能说清不同算法的优缺点与取舍，能做有限修改与优化，理解底层逻辑
- **优秀**：能完全理解算法原理，能以开源代码为基础搭出战队自己的自瞄 / 导航代码，能把 YOLO 与 cv 库结合使用，能针对性地改进算法

## 附录 A 术语速查

| 术语 | 含义 |
|---|---|
| 自瞄 | 对移动装甲板自动瞄准 + 自动火控 |
| 击杀时间 | 打死敌方单位所需时间，自瞄效果的金标准 |
| 灯条 / 装甲板 | 装甲板由两条发光灯条组成，四个角点是所有几何计算的物理基础 |
| PnP | 从已知的 3D 点和图像 2D 点求解相机位姿 |
| EKF | 扩展卡尔曼滤波，用于估计目标运动状态 |
| MPC | 模型预测控制，用优化方法求未来一段时间的最优轨迹 |
| LIO | 激光惯性里程计，点云 + IMU 推算自身运动 |
| SLAM | 同时定位与建图 |
| costmap | 代价地图，标注哪些格子能走、代价多少 |
| 行为树 | 用树状结构组织机器人决策逻辑，Nav2 用它编排导航行为 |

## 附录 B 看开源的方法（两种思维）

看任何开源项目，先问三个问题：

1. **它怎么跑起来的** —— 数据从哪进、经过哪些模块、从哪出
2. **它的依据是什么** —— 基于哪篇论文、哪个理论
3. **它的局限在哪** —— 依据里的假设一旦不成立，会在哪里失效

配合两种思维：

- **模块化**：分成几层、每层负责什么、层与层之间的接口是什么
- **系统化**：这些模块怎么串成一条能跑通的线

验收标准：合上代码，能在脑子里画出框架图。

选材原则：优先看生态好、用的人多的。导航就是 Nav2，生态成熟、资料多、出问题好查。哈工大的开源很强，但结构过于复杂，不适合当入门材料——留到有判断力之后再看。
